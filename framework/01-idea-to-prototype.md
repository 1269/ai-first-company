# Idea to Prototype

> Companion guide to Videos 7-8: Building an app from scratch with AI, and the GSD Framework in action.

## The Goal

Go from "I have an idea" to "I have a working demo" in a single weekend. Not a mockup. Not a slide deck. A thing that works.

## The Process

### 1. Define the Problem (30 minutes)

Before you write a single line of code or prompt, answer three questions:

- **Who has this problem?** Be specific. Not "everyone" — a real person you can describe.
- **What are they doing today?** The current workaround, even if it's manual and painful.
- **What would "solved" look like?** The simplest version that would make them switch.

Write this down. One paragraph. This is your anchor for every decision that follows.

### 2. Scope the Prototype (30 minutes)

A prototype proves one thing: **this idea can work.** It doesn't need to be pretty, handle edge cases, or scale.

List everything you think the product needs. Then cut it in half. Then cut it in half again. What's left is your prototype scope.

**Rules:**
- Maximum 3 features
- No user authentication (use a hardcoded user or skip it)
- No payment processing
- No custom design — use a UI library or templates
- One happy path, no error handling

### 3. Build With AI (1-2 days)

This is where AI changes everything. Instead of spending weeks on boilerplate, you:

1. **Describe your prototype** to an AI coding assistant in plain language
2. **Generate the scaffold** — project structure, dependencies, basic UI
3. **Build feature by feature** — one prompt per feature, test as you go
4. **Debug together** — paste errors, get fixes, iterate fast

The key insight: you're directing, not coding. You decide what to build. AI helps you build it. Your judgment is the product — the code is just the implementation.

### 4. Test With One Person (1 hour)

Show it to one person who has the problem you're solving. Not a friend who'll be nice — someone who actually needs this.

Watch them use it. Don't explain. Don't help. Just watch.

What confused them? What did they try to do that didn't work? What did they say they wished it could do? Write all of this down.

### 5. Decide: Continue or Kill (15 minutes)

Based on that one test:

- **Continue** if the person understood the value and wanted to use it again
- **Pivot** if they liked the idea but the execution missed the mark
- **Kill** if the problem isn't real or urgent enough to solve

Killing a weekend prototype is free. Killing a 6-month project is expensive. This is why you prototype first.
